# ANO 命名规范与历史名映射（v1.0，2026-11-02 Govern 裁定）

## 1. 项目正式名

**ANO = AIV NVMe-oF Offload**（NVMe-oF 命令面 AIV 卸载）。

语义：在昇腾 AIV（AI Vector）核内完成 NVMe-oF 命令面的 SQE 生产、WRITE_WITH_NOTIFY 发射与回执收割，host 稳态零参与；UB fabric 为运输底座。

## 2. 分层命名规范（新产物一律遵守）

| 层 | 正式名 | 语义 |
|---|---|---|
| 项目/交付包 | `ano_offload_pkg` / `ano_offload_pkg_YYYYMMDD.tar.gz` | 可部署交付包 |
| 原型树（命令面+回执面） | `ano_wn/` | WRITE_WITH_NOTIFY 形态原型（wn = with-notify） |
| 发射侧 | `wn_host`（二进制）/ `wn_host.cpp` | client 角色：SQE 生产+发射+回执收割 |
| 软 TGT | `tgt_wn` / `tgt_wn.cpp` | server 角色：对端扮演（真 TGT 到位后整层退役） |
| AIV 探针通道算子 | **AnoProbe**（aclnn 面 `aclnnAnoProbe*`） | mode0 读 / mode1 写 / mode3 发射三通道 |
| 状态机算子（未来工作） | **AnoSm** | 15-a 交接状态机的后续演进用此名 |
| 环境变量 | `ANO_*`（如 ANO_DEV_BASE、ANO_STOPF） | 部署/编排脚本 |
| 退役形态存档 | `ano_send/`（如日后启用） | SEND 形态（本环境已证不可用，封存） |

## 3. 历史名 → 正式名映射表（钉死在案，不再变动）

| 历史名（在案身份，保留不改） | 正式名 | 处理方式 |
|---|---|---|
| `hov_offload_pkg`（≤v3 交付包） | `ano_offload_pkg` | 实际改名（v4 起重打包） |
| `hov_wn/`（taskM39 原型树） | `ano_wn/` | 新树承接，原树封存不动 |
| **N2AivProbe**（算子，taskM12b 产物） | **AnoProbe** | **实际改名重建**（新 vendor 树；wn_host/tgt_wn 重新编译链接；新基线经单发+八连发重建） |
| `HovSm` / `hov_sm.cpp`（15-a 状态机，六件之一） | AnoSm（未来） | **不改名**——md5 钉住证据链（`c24c33af…`），永久保留历史名；映射仅文档级 |
| `hov_proto.h` / `hov_host.cpp` / `hov_xlate.h` / `hcomm_probe.cpp` / `demo.py`（六件） | 无对应新名 | **不改名**——六件禁改纪律不变，永久历史身份 |
| `hov_send/` 封存六件 | ano_send（如启用） | **不改名**——封存件只读 |
| `n2_udma_internal.h`（线格式布局头） | 同名沿用 | **不改名**——soft_tgt 钉住区共享头，新树经 -I 引用同一文件 |
| `HOVO_*` 环境变量 | `ANO_*` | 实际改名（脚本层，不影响二进制） |
| `/tmp/hcomm_*` `/tmp/wn_*_lijiawen` 运行时标志文件 | 同名沿用 | 不改名——硬编码于二进制内，改名无收益 |

## 4. 纪律

1. 新代码、新文件、新文档一律用正式名；引用历史件时保留原名并可在首次出现处括注正式名。
2. 六件+hov_send 封存件+n2_udma_internal.h 的 md5 基线不因命名调整而变化；动手前/收工双端自证照旧。
3. AnoProbe 重建后的新基线（算子包/二进制/单发+八连发日志 md5）以 taskM42 REPORT 为准，旧 N2AivProbe 基线（`feb653b3…` 等）转入历史映射，不再作为现行判据。
