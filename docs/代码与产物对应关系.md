# 代码 ↔ 编译产物 ↔ 功能作用 对应关系

本包全部产物为项目自研；第三方依赖（CANN/liburma/驱动固件）不进包，见 `third_party/DEPENDENCIES.md`。

## 1. 总览表

| 源码（src/） | 编译产物（bin/） | 功能作用 | 构建方式 |
|---|---|---|---|
| `ano_wn/wn_host.cpp` | `bin/wn_host`（md5 `7feb3720…`） | **发射侧原型**：建链→96B SQE 生产→WRITE_WITH_NOTIFY 双块 WQE 发射→CQE 收割→回执 AIV 图内轮询收割 | `scripts/build.sh`（g++ 在案命令） |
| `ano_wn/tgt_wn.cpp` | `bin/tgt_wn`（md5 `32108655…`） | **软 TGT（扮演对端）**：命令收件箱→SQE 解析+key 校验→模拟取数→回执两发 WRITE | 同上 |
| `aiv_probe/`（op_kernel+op_host） | `bin/opp_vendor/vendors/customize/`（算子 vendor 包） | **AnoProbe 算子（历史名 AnoProbe）**：AIV 三通道（mode0 读/mode1 写/mode3 发射），wn_host 与 tgt_wn 的 AIV 能力底座 | msopgen/CMake（任务 12-b 产物，随包交付不现场重建） |
| `include/n2_udma_internal.h` | 无（纯编译期头文件） | UB 线格式布局定义（`n2_jfs_sqe_ctl`/`n2_wqe_sge`/`n2_jfc_cqe`），wn_host/tgt_wn 共有 | 被 build.sh 经 `-I src/include` 引用 |

## 2. 发射侧：wn_host.cpp → bin/wn_host

子命令（`main()` 分发）与功能段对照：

| 子命令 | 功能段 | 作用 |
|---|---|---|
| `wnfire <dev> <idx> <phy> <N>` | wnfire 段 | **命令面+回执面主流程**（本包核心）：104B 载荷（8B 控制头+96B SQE）→ 128B 双块 WQE（WRITE 填单+NotifyCtx）→ AIV 上环敲门 → CQ owner-bit 收割 → **AIV 图内回执收割**（valid 轮询→256B 读取比对→清位复用） |
| `client` | run_side 公共段 | 只建链+快照+守候（deploy_check dry-run 用，零发射） |
| `sendsq` / `bench` | 对应功能段 | 历史形态留存（SEND 已退役/bench 测量），部署不用 |

关键偏移常量（单变量纪律钉死）：回执 cqe_buf=`dbuf+0x100`（32B，valid@byte16）、回执数据=`dbuf+0x200`（256B）、发射载荷 staging=`dbuf+0x400`、对端收件箱=`remoteBuf+0x800`。

## 3. 软 TGT：tgt_wn.cpp → bin/tgt_wn

| 子命令 | 功能段 | 作用 |
|---|---|---|
| `wnrecv <dev> <idx> <phy> <N>` | wnrecv 段 | **对端扮演主流程**：收件箱（自有 dbuf+0x800 起 8 槽×128B）AIV 轮询槽 valid → 解析 96B SQE（opcode/nsid/slba/keyed SGL）→ key 与 channel token 比对 → 模拟 KV 取数（递增图案）→ 回执两发 WRITE（数据 256B→对端+0x200；cqe_buf 32B→对端+0x100，数据先行 valid 殿后） |
| `server` | run_side 公共段 | 只建链+守候（deploy_check dry-run 用） |
| `wpoll` / `tgtsq` / `bench` | 对应功能段 | 历史探针/验证形态留存，部署不用 |

真 TGT 到位后 wnrecv 扮演段整层退役，wn_host 一行不动（缝合点见 `docs/真TGT缝合点.md`）。

## 4. AIV 能力底座：src/aiv_probe/ → bin/opp_vendor/

源码与 vendor 包内物的对应：

| 源码 | vendor 包内产物 | 作用 |
|---|---|---|
| `op_kernel/n2_aiv_probe.cpp` | `op_impl/ai_core/tbe/kernel/`（kernel 二进制）+ `customize_impl/dynamic/n2_aiv_probe.cpp`（注册副本） | AIV kernel 本体：mode0=GM 读 ≤64B、mode1=st_dev 写 u32、mode3=WQE 上环+门铃双写 |
| `op_kernel/n2_aiv_probe_tiling.h` | `op_impl/ai_core/tbe/config/ascend950/aic-ascend950-ops-info.json` 等 | tiling/算子信息注册 |
| `op_host/n2_aiv_probe.cpp` | `op_proto/`（shape 推导注册）+ `op_api/include/aclnn_n2_aiv_probe.h` + `op_api/lib/libcust_opapi.so` | host 侧注册与 aclnn 调用面——**wn_host/tgt_wn 链接 `-lcust_opapi` 即此** |

运行时加载链：`ASCEND_CUSTOM_OPP_PATH`（包内 vendor）+ `opp_merged/` 农场（deploy_check 重建：系统 opp 内置件 + 包内 custom 件）→ aclnn 调 `aclnnAnoProbe` 即路由到本算子。

## 5. 脚本与运行链路

| 脚本 | 作用 | 与产物的关系 |
|---|---|---|
| `scripts/env.sh` | 环境变量集中（ASCEND_HOME_PATH/CUSTOM_OPP_PATH/LD_LIBRARY_PATH/标志文件路径） | 被以下三件 source |
| `scripts/build.sh` | `src/ano_wn/*.cpp → bin/wn_host, bin/tgt_wn`（在案 g++ 命令封装） | 重编译入口；运行时以包内预编译件为准 |
| `scripts/deploy_check.sh` | 部署自检（健康/CANN 版本/MANIFEST/opp 农场/dry-run 建链） | 调 `bin/tgt_wn server` + `bin/wn_host client`（零发射） |
| `scripts/run_direct.sh` | 联跑编排（tgt 后台+wn 前台+标志文件握手） | 调 `bin/tgt_wn wnrecv` + `bin/wn_host wnfire` |
| `scripts/wn_pair.sh` | 开发机在案编排**原样存档**（含开发机绝对路径） | 存档保真，部署不用 |

## 6. 一次单发联跑的产物协同时序

```
deploy_check:  bin/tgt_wn server ─┐ 仅建链+快照（零 WQE）
               bin/wn_host client ┘
run_direct 1:  bin/tgt_wn wnrecv ── 收件箱就绪(AIV mode0 轮询槽 valid)
               bin/wn_host wnfire ─ 96B SQE 组装 → 双块 WQE(AIV mode3 上环+敲门)
                                    → UB 网络 → tgt 收件箱落槽+notify 置 valid
               tgt: 解析+key 校验 → 取数 → 回执 WRITE×2 → client dbuf+0x200/+0x100
               wn:  CQ 收割(AIV mode0) → 回执 valid 轮询(mode0) → 256B 比对(mode0×4)
                    → 清位(mode1) → [PASS]
```
