# 搭建与调测手册：ANO——KV Cache 跨节点卸载原型（ano_offload_pkg）

版本：v2.0 ｜ 日期：2026-11-02 ｜ 读者：未参与本项目的工程师——按本手册可从零完成部署、跑通闭环、定位常见问题

---

## 0. 这套工具是什么（30 秒版）

两个进程，跑在两台 UB 互通的机器（或同机双卡）上：

- **tgt_wn**（存储侧）：扮演 NVMe-oF Target。建链后等待命令落入"命令收件箱"，解析 NVMe 读命令，把数据+回执经 RDMA WRITE 直写对端 NPU 的 HBM；
- **wn_host**（推理侧）：在 NPU 的 AIV 核内组装 NVMe 读命令，经 UB 硬件（WRITE_WITH_NOTIFY 语义）直写对端收件箱并通知对方，然后在图内收割回执。

跑通的标志：wn_host 打印 `[PASS] wnfire 回执面 AIV 图内闭环`。

## 1. 环境准备

| 项 | 要求 | 检查命令 |
|---|---|---|
| 硬件 | 昇腾 950DT/950PR，≥2 张 NPU（或双机各 ≥1） | `npu-smi info` 全绿 |
| CANN | 9.3.0（其他版本未验证） | `echo $ASCEND_HOME_PATH` 指向 cann-9.3.0 |
| 驱动/固件基线 | 驱动 25.6.rc2.b023／固件 7.0.9.100.202（实测通过面） | `npu-smi info -t board -i <id>` |
| 编译器 | g++ 支持 `-std=c++17` | `g++ --version` |
| 权限 | 容器内需可访问 device（/dev/davinci*）；**全程无需 root、严禁重启** | — |

**设备纪律（重要）**：默认实跑仅使用 device 1、2；device 0/3 为保留样本，**严禁**在其上发射任何命令。`scripts/env.sh` 中 `ANO_DEV_BASE=1` 控制 rank→device 映射，勿改除非你知道在做什么。

## 2. 获取与校验

```bash
tar xzf ano_offload_pkg_YYYYMMDD.tar.gz && cd ano_offload_pkg
md5sum -c MANIFEST.md5        # 全部 OK 才继续；任何 FAIL 说明包损坏，重新获取
```

## 3. 编译

```bash
source scripts/env.sh
./scripts/build.sh            # 出错即停；成功后产物在 bin/（wn_host / tgt_wn / AIV 算子）
```

预编译二进制已随包提供（bin/），环境一致时可跳过编译。包内源码改动后必须重跑 build.sh 并更新 MANIFEST。

## 4. 文件结构与代码地图

```
src/
├── hov_wn/
│   ├── wn_host.cpp           # 推理侧主程序
│   └── tgt_wn.cpp            # 存储侧软 TGT
├── aiv_probe/                # AnoProbe AIV 算子（mode0=读 HBM / mode1=写 HBM / mode3=发射 / mode4=全链一体）
└── include/                  # 布局常量（inbox/回执区偏移，两端共用）
```

读代码时对照这张布局图（两端 HBM 里的数据结构）：

```
对端（tgt 侧 HBM dbuf）                 本端（wn_host 侧 HBM dbuf）
inbox @ dbuf+0x800                      cqe_va @ dbuf+0x100（32B 回执头）
┌────────┬─────────┬─────┐ ×8 槽        data_va @ dbuf+0x200（256B 回执载荷）
│8B 控制头│96B 命令  │ pad │  /128B      valid 位 @ cqe_va+16；清位=写该处 u32
└────────┴─────────┴─────┘
控制头=notify 落点（valid）              tgt_wn 回执写这里，wn_host 的 AIV 轮询这里
```

关键代码锚点：

| 位置 | 内容 |
|---|---|
| wn_host.cpp 发射循环 | 组 128B 双块 WQE（数据块+通知块）→无害门铃→真门铃 |
| wn_host.cpp "4.5) AIV 图内回执收割" | 轮询 valid→读 256B 比对→清位 |
| tgt_wn.cpp :598/:605 | 回执落点定义 |
| include/ 布局头文件 | 所有偏移常量的唯一出处，两端必须一致 |

## 5. 联跑

### 单发（首次验证）

```bash
./scripts/wn_pair.sh 1        # 无调度环境用 ./scripts/run_direct.sh 1
```

wn_host 侧预期：

```
wnfire：第 0 发 cid=0 head=0→2 rc=0
wnfire：CQE status=0 substatus=0 owner=1
wnfire：第 0 发回执 AIV 收割 valid=1 cid=0 数据=MATCH（已清位）
[PASS] wnfire 回执面 AIV 图内闭环（1/1 发 CQE=0 + 1/1 发回执 AIV 侧 MATCH）
```

tgt_wn 侧预期：`槽 0 解析 opcode=0x2/slba=8/key MATCH → 回执 WRITE#1/#2 rc=0`。

### 八连发（稳定性回归）

```bash
./scripts/wn_pair.sh 8
```

预期：8/8 CQE status=0、8/8 回执 AIV 侧 MATCH、逐发清位复用。**注意：进程退出码 130（"任务超时 300s"）不判负**——那是调度包装层的收尾时限，只要 PASS 行已打印即为成功。

## 6. 排障速查

| 现象 | 含义 | 处置 |
|---|---|---|
| CQE status=0 但 PASS 未出 | 回执收割超时：落点偏移两端不一致 | 核对 include/ 布局常量两端一致；核对 tgt 侧回执 WRITE rc=0 |
| CQE status=3 | 发射了 AIV 引擎不支持的语义（本工具只应用 opcode=5） | 检查是否误改 opcode；对照设计文档 §5 |
| CQE status=5 | 本端访问校验拒绝（设备态异常） | 换健康 device 复现；持续复现则按 docs/ 外报障流程走（收集 npu-smi+日志） |
| 单发 PASS、连发失败 | 槽位复用问题：valid 未清位或控制头被覆写 | 查清位写点是否精确命中 cqe_va+16；notify 数据值必须为 1 |
| 建链不 READY | 环境/设备问题 | npu-smi 健康检查；确认双卡/双机 UB 互通；确认 ANO_DEV_BASE 映射 |
| exit=130 | 调度包装层 300s 时限 | 看日志是否已 PASS；是则忽略 |
| md5 校验 FAIL | 包损坏或被改动 | 重新获取；不要带病运行 |

**排障三原则**：①一次只改一个变量；②先看 tgt 侧日志（命令到没到）再看本端（回执收没收），把故障段切成两半；③任何复现都要留日志原文，不凭记忆描述现象。
